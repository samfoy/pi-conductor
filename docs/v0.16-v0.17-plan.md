### v0.17-S4: Turn-limit enforcement loop + grace message injection

**Critic gate: YES** — core behavior change; two distinct code paths (steerable vs non-steerable).

**Goal:** After each `applyEvent` call in `processLine`, if `run.maxTurns` is set and `run.usage.turns >= run.maxTurns` and not already in grace period and not already terminal: enter grace handling. For steerable: enqueue a wrap-up RPC message, set `gracePeriodActive = true`, set `gracePeriodStartTurn`. For non-steerable: call `forceTerminate(run, "aborted", ...)` immediately. When `gracePeriodActive` and `run.usage.turns >= gracePeriodStartTurn + run.graceTurns`: call `forceTerminate(run, "aborted", ...)`.

**Files:**
- `src/runs.ts` — in `processLine`, after the `if (effect.kind === "finalize")` block: add turn-limit check. Extract to a helper `checkTurnLimit(run, opts)` for testability. The helper:
  - Returns early if `!run.maxTurns || isTerminal(run.status)`
  - Grace entry: `!run.gracePeriodActive && run.usage.turns >= run.maxTurns`
  - Grace escalation: `run.gracePeriodActive && run.usage.turns >= run.gracePeriodStartTurn! + run.graceTurns`
  - Non-steerable at limit: `forceTerminate(run, "aborted", opts.registry, opts.onComplete)` with `run.errorMessage = "turn limit reached (non-steerable: no grace period)"`
  - Steerable grace message: `enqueueRpcSendWithAck(run, "follow_up", GRACE_MESSAGE)` where `GRACE_MESSAGE` is a pinned constant.
- `src/runs.ts` — `forceTerminate`: add `reason === "aborted"` branch → sets `run.status = "aborted"`.
- `src/runs.ts` — add exported `GRACE_MESSAGE` constant (pinned string for tests).

**Witnesses to pin (WDD):**
- W1: `GRACE_MESSAGE` contains "wrap up" (case-insensitive) — pin exact string
- W2: `forceTerminate(run, "aborted", ...)` sets `run.status === "aborted"` and `run.errorMessage` starts with `"turn limit"`
- W3: Non-steerable run at `maxTurns = 3`: `forceTerminate` called on the 3rd `message_end` event; never called on 2nd
- W4: Steerable run: grace message enqueued on turn N; `forceTerminate` called on turn N + `graceTurns`; NOT before
- W5: Natural completion before `maxTurns`: `forceTerminate` never called, `gracePeriodActive` stays `false`
- W6: Idempotency — second `checkTurnLimit` call on an already-`"aborted"` run is a strict no-op (status unchanged, no second enqueue)

**Acceptance:**
- `checkTurnLimit` is a named export or at minimum a named inner function (injectable for unit tests)
- Test suite covers W3–W6 with injected `applyEvent` mocks (no real subprocess)
- `applyChainIfPresent` is NOT called when `run.status === "aborted"` (chain guard `terminal !== "completed"` already handles this — verify with a test)

**Verification:**
