## Goal

Today the conductor is a **supervised** orchestrator: the parent LLM decides each spawn turn by
turn, a human watches the stream, and chains (v0.15) are the only automatic multi-step shape —
a fixed `then` edge with no adaptation, no retry-with-diagnosis, and no cross-session learning.

Metaphor demonstrated three patterns that make an *autonomous* multi-agent loop trustworthy.
This design ports them and composes them into a new autonomous mode:

1. **Failure classification → classified retry** (Metaphor's failure taxonomy).
   Every non-`completed` terminal gets a `FailureClass`; a retry policy decides whether to
   re-spawn with diagnostic context, instead of the current "hard-stall → kill → dead" path.
2. **Plans-as-hypotheses re-evaluation** (Metaphor's `RePlanner`).
   Between chain steps, a lightweight evaluation decides: proceed, adapt the next step, insert
   a remediation step, or stop. Chains become adaptive DAGs rather than fixed edges.
3. **Confidence-weighted cross-session memory** (Metaphor's `MemoryStore`).
   Record `(persona, task-shape) → outcome`, weight by confidence and recency, and bias future
   spawn/persona selection. The conductor learns which spawn shapes succeed.
4. **Autonomous mode** — the umbrella. `/conductor auto "<goal>"` runs a persona chain/DAG to a
   terminal outcome with re-plan + classified-retry + memory, escalating to the human only on
   exhausted retries, permission gates, or an explicit stop condition.

Each of 1–3 is independently useful and ships as its own slice; 4 composes them.

## Feature 1 — Failure classification + classified retry

### 1a. The taxonomy (`src/failure-classify.ts`, pure)

Mirrors `src/watchdog.ts`: a pure module, no I/O, no clock. Metaphor's categories, adapted to
pi-conductor's terminal statuses:

```typescript
export type FailureClass =
  | "syntax"      // build/compile/parse error in the sub-agent's output
  | "logic"       // test assertions failed (code ran, wrong result)
  | "test"        // test harness/runner failed to execute (infra of tests)
  | "environment" // missing dep, brazil-build/npm setup, path, tool not found
  | "permission"  // denied host op / tool permission / auth (mwinit) failure
  | "timeout"     // wall-clock timeout terminal
  | "stall"       // watchdog hard-stall kill
  | "turns"       // turn-limit abort (v0.17 "aborted")
  | "unknown";    // classifier could not decide

export interface FailureSignal {
  terminal: RunStatus;              // failed | killed | timeout | aborted | hook_failed | merge_conflict
  exitCode?: number;
  stderrTail: string;               // last N KB of stderr
  errorMessage?: string;
  terminationReason?: TerminationReason; // killed | timeout | stalled | aborted
}

export function classifyFailure(sig: FailureSignal): FailureClass;
```

Classification is **priority-ordered**: terminal/reason first (deterministic — `timeout`→timeout,
`stalled`→stall, `aborted`→turns, `merge_conflict`→logic), then regex probes over
`stderrTail`+`errorMessage` for the ambiguous `failed`/`hook_failed` cases (permission > environment
> syntax > test > logic). Deterministic-first keeps the fuzzy layer from overriding a known cause.
Probe patterns live in an exported, testable `PROBES` table.

### 1b. The retry decision (pure)

```typescript
export interface RetryPolicy {
  maxAttempts: number;                       // total attempts incl. the first (default 1 = no retry)
  retryableClasses: readonly FailureClass[]; // default: ["environment","stall","timeout","test"]
}

export function shouldRetry(cls: FailureClass, attempt: number, policy: RetryPolicy): boolean;
```

`logic`/`syntax` are **not** retried by default — re-running the same prompt reproduces the same
wrong answer (Metaphor's lesson: retry the flaky, escalate the deterministic). `permission` is not
retried — it needs a human. `environment`/`stall`/`timeout`/`test` are transient-ish and get a
retry with diagnostic context injected into the re-spawn task.

### 1c. Wiring (this slice does 1a+1b + attach; respawn loop is 1d, staged with Feature 4)

- New `Run.failureClass?: FailureClass` and `Run.retryAttempt?: number` (default 0).
- In `finalize()` (`src/runs.ts`), when `terminal !== "completed"`, compute and stamp
  `run.failureClass` before persistence. Additive; no behavior change to existing paths.
- Surface in `RunRecord`, `emitFinalizeEvent`'s failed payload, `/conductor doctor`, and
  `/conductor history` annotations.
- **1d (staged):** the classified-retry re-spawn loop lives in the autonomous executor
  (Feature 4) and behind `kill_on_stall`/policy for supervised spawns. Config cascade adds a
  `retry` block to `WatchdogConfigDefaults` sibling in `ConductorConfig`.

**Decision — unstamped terminal paths (intentional).** Orphan/reconcile paths
(`reconcile-startup.ts`, `gc/reconcile.ts`) flip stale `running` records to `killed` without a
class. This is deliberate: an orphaned run (parent pi crashed) has no diagnostic signal, so its
class is semantically `unknown` — the classifier's default. We do NOT stamp there. The three live
stamp sites (`forceTerminate`, `finalize` natural-exit, spawn-error catch) cover every path where a
diagnostic actually exists.

### Config

```jsonc
{ "retry": { "maxAttempts": 1, "retryableClasses": ["environment","stall","timeout","test"] } }
```

Per-call `ensemble_spawn` arg `retry_max_attempts` and persona frontmatter `retry_max_attempts`
join the standard cascade (per-call > project > user > persona > default).

## Feature 2 — Plans-as-hypotheses re-evaluation

Extends v0.15 chains (`src/chain.ts`). Today `resolveChain` returns a fixed `{ then }` edge.
Add an optional **re-eval step** between a completed run and its chain successor:

```typescript
export interface ChainStep {
  then: string;
  taskTemplate?: string;
  timeoutMinutes?: number;
  reevaluate?: boolean;   // NEW — run a re-plan check before spawning `then`
}
```

When `reevaluate` is set, before spawning the successor the conductor consults a **re-plan
verdict** derived from the parent run's `final.md` + `failureClass`:

```typescript
export type ReplanVerdict =
  | { kind: "proceed" }                          // spawn `then` as planned
  | { kind: "adapt"; persona: string; task: string } // spawn a different successor
  | { kind: "insert"; persona: string; task: string } // spawn a remediation step first, then `then`
  | { kind: "stop"; reason: string };            // halt the chain, escalate to human

export function evaluateChainOutcome(input: {
  parentFinal: string;
  parentFailureClass?: FailureClass;
  step: ChainStep;
}): ReplanVerdict;
```

Slice ships a **deterministic** heuristic verdict (e.g. `stop` on non-retryable failure class,
`insert` an `investigator` on `environment`, `proceed` otherwise) so it's testable without an LLM
call. An LLM-backed verdict is a later enhancement gated behind autonomous mode. Metaphor's rule:
"the first plan is always incomplete" — the re-eval is what lets the chain revise.

## Feature 3 — Confidence-weighted cross-session memory

New store at `~/.pi/agent/conductor/memory/outcomes.jsonl` (append-only; compacted on GC).

```typescript
export interface OutcomeRecord {
  persona: string;
  taskShape: string;      // normalized signature: lowercased verbs/nouns hash, not raw task
  status: RunStatus;
  failureClass?: FailureClass;
  durationMs: number;
  ts: number;
}

export interface PersonaScore {
  persona: string;
  taskShape: string;
  successRate: number;    // confidence-weighted, recency-decayed
  n: number;
}

export function recordOutcome(rec: OutcomeRecord): void;             // append on finalize
export function scoreForShape(shape: string): PersonaScore[];        // ranked personas
```

Weighting mirrors Metaphor's MemoryStore: confidence rises with `n`, decays with recency
(half-life ~30 days), adjusted by retrieval usefulness. The conductor prompt addendum surfaces the
top-scoring persona for a detected task shape as a *hint* — never a hard override (the LLM still
chooses). Privacy: `taskShape` is a hash of normalized tokens, not the raw task text.

**Cross-cutting; lowest priority.** Ships last because it's the least load-bearing for autonomy —
useful polish, not a correctness requirement.

**Deferred decisions (S4 scope boundaries):**
- **Unbounded growth.** `outcomes.jsonl` is append-only with no compaction. Acceptable for S4
  (~5 MB/yr at 100 runs/day); a GC hook or ring-buffer cap is a follow-up tracked for the GC
  subsystem, NOT silently ignored. `scoreForShape` reads the whole file per call — fine at this
  scale, revisit if the file grows large.
- **Spawn-error runs are NOT recorded.** The in-process spawn-error catch (`runs.ts`) stamps
  `failureClass` but does not call `recordRunOutcome` — a spawn failure (`pi ENOENT`) reflects
  infrastructure, not persona competence, so it must not pollute the persona's success rate.
  Recording fires only from the two finalize terminal paths.
- **Test isolation.** `memoryPath()` honors `CONDUCTOR_MEMORY_PATH`; the npm `test` script points
  it at a throwaway temp file so unit runs never touch the real user store. The finalize→record
  wiring is witnessed by a live-gated integration test (real subprocess required).
- **Recommend score is not a raw success %.** The recency decay lives in the numerator while the
  small-sample prior lives in the denominator, so the surfaced number is a *ranking score*, not a
  probability. `ensemble_recommend` labels it "score," not "% success," to avoid misinforming the
  human.

## Feature 4 — Autonomous mode

`/conductor auto "<goal>" [--max-steps N] [--budget-usd X]` and an `ensemble_auto` tool.
The conductor runs a loop:

```
plan (LLM decomposes goal → persona DAG)
  → for each ready node:
      spawn persona (with memory hint)
      on terminal:
        classify failure (F1)
        if !completed && shouldRetry: re-spawn with diagnostics (F1d), else
        re-evaluate (F2): proceed | adapt | insert | stop
      record outcome (F3)
  → converge: finalizer synthesizes; escalate to human on stop/exhausted-retry/permission-gate
```

Guardrails (Metaphor's "invariants enforced by architecture", pi-conductor's overseer posture):

- **Human ceiling.** Autonomous mode cannot exceed permissions/tools the human approved at start.
  Permission-class failures always escalate, never auto-retry.
- **Budget + step caps.** Hard `--max-steps` and optional `--budget-usd`; watchdog `kill_on_stall`
  defaults ON in auto mode (opposite of supervised default).
- **Write-capable serialization.** Existing `maxConcurrentWriteCapable` cap still applies; auto
  mode respects worktree isolation for parallel builders.
- **Always resumable + observable.** Every step is a normal run record; the human can `Ctrl+G` into
  any step, `/conductor stop`, or `ensemble_send` to steer mid-loop.

Composes F1 (retry), F2 (adapt), F3 (persona selection). Ships last, after 1–3 land and stabilize.

**S5 implementation decisions (as shipped):**
- **Plan is caller-supplied.** `ensemble_auto` takes an explicit ordered `steps[]` (the conductor
  LLM is the planner). No in-executor LLM decomposition — keeps the loop deterministic and testable.
- **The executor is the sole retry authority.** Its `spawnStep` passes neither `onRetry` (S2) nor
  `onChain` (v0.15) — retries are driven in-loop and awaited, so every retry counts against
  `maxSteps` and there is no double-fire with S2's background retry or the default builder→critic
  chain.
- **Kill-safety via `awaitTerminal`.** Operator kills (`ensemble_kill` / `/conductor kill`) and
  queue-cancels `forceTerminate` a run WITHOUT firing `onComplete`. `spawnStep` resolves on ANY
  terminal status via a `registry.onChange` backstop (once-guarded against the `onComplete` fast
  path), so stopping a sub-step mid-loop unblocks the executor instead of hanging it.
- **Per-substep notifications (accepted).** Each internal step emits a `<sub-agent-completed>`
  card. A follow-up could batch these behind one run-level summary; not a correctness issue.
- **Queued-drain drops `retryAttempt` (accepted).** A queued-then-drained step persists
  `retryAttempt=0` — observability drift only; the executor's local attempt counter is
  authoritative.
